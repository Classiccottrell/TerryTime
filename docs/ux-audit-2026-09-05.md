# TerryTime UX/Design Audit — 2026-09-05

Scope: `app/`, `components/`, `public/` as of this commit. Read-only audit; no code changed.

## Summary

TerryTime is not one storefront — it's a chooser page (`/shop`) plus five parallel storefront directions (`city`, `archive`, `shrine`, `stencil`, `grid`), all sharing one cobalt-on-bone design language defined in `app/globals.css` (`.shop-design` block). The visual system is genuinely distinctive (raw borders, mono type, high-contrast cobalt, hand-tuned collage layouts) and avoids most default-LLM tells. Real product photography is used throughout (`public/img/products/*`, `public/img/shop/*`) rather than placeholder blocks.

Main risks are: (1) unresolved product decision — five parallel storefronts is itself a UX problem, not a design pass; (2) several hard a11y/interaction issues (disabled BuyButton with no visible state change, hover-only 3D mascot with no touch fallback, `aria-hidden` decorative structure carrying real wayfinding text); (3) a few Section 4.7-style hard-rule violations (nav item count on mobile, oversized hero type risk, eyebrow overuse is arguably intentional/consistent here rather than templated).

## UX/best-practice findings (ui-ux-pro-max-skill)

1. **Five duplicate storefronts = decision-paralysis anti-pattern, not five products.** `app/shop/page.tsx` presents `city`, `archive`, `shrine`, `stencil`, `grid` as equal peer choices with identical catalog (`lib/products`). This is a legitimate design-review artifact but is currently shipped as the site's own home route (`app/page.tsx` redirects `/` → `/shop`, the chooser). A visitor arriving at the real site lands on a meta-page about design options, not a store. This needs to resolve to one shipped direction before launch — the audit flags it as the single highest-priority UX issue, ahead of any component-level fix.

2. **BuyButton disabled state has no visible feedback (`components/BuyButton.tsx`).** `disabled={loading || isStaticExport}` relies solely on `disabled:opacity-60` in Tailwind classes for the Tailwind variant, but the same button is restyled by `.shop-design .shop-purchase button` in `globals.css`, which forces `background`/`color` with `!important` and only handles `:hover` — no `:disabled` rule exists in that override block (lines 252–271). On the actual shop pages (city/archive/shrine/stencil/grid, all wrapped in `.shop-design`), a disabled Buy button looks fully interactAnd just now. ive. Matches the skill's mandatory Interactive UI States checklist (disabled states must be visually distinct).

3. **Mascot3D has no touch/keyboard interaction path (`components/Mascot3D.tsx`).** Tilt effect is wired via `onMouseMove`/`onMouseLeave` only. On mobile (this is a merch shop selling to real customers), the hero face element (`city-hero__face`, `shrine-hero__face`, etc.) is inert — not broken, but a missed hero moment on the majority of commerce traffic. No `prefers-reduced-motion` guard here either (the CSS-side reduced-motion query at the bottom of `globals.css` only disables `.shop-design *` transitions/animations, not this inline `style.transform` write, so users with reduced-motion set still get the JS-driven parallax tilt).

4. **Decorative wayfinding elements marked `aria-hidden` carry real content.** `city-hero__signal` (`app/shop/city/page.tsx` line 29) and `city-hero__route` (line 44) are `aria-hidden="true"` but contain the only copy indicating location/coordinates and cross-street context — screen reader users lose this entirely, and it's not purely decorative (it reads as real navigational/brand copy, "Commercial / Broadway / Main"). Same pattern likely repeats in the other four shop pages (not fully audited line-by-line, but `shop-kicker`/`aria-hidden` icon patterns recur across `archive`, `shrine`, `stencil`).

5. **Mobile nav still shows all N shop links in a horizontal scroll strip, not a condensed/hamburger pattern (`components/ShopNavigation.tsx` + `globals.css` `.shop-nav` mobile block, lines 745–750).** At `max-width: 760px`, `.shop-nav ol { overflow-x: auto }` turns the 5-way shop switcher into a horizontally-scrollable pill row. Functional, but the ui-ux-pro-max `ux` domain flags condensing/hamburger over horizontal-scroll-nav as the preferred mobile pattern once item count exceeds ~4 (here it's home + 5 shop links = 6 nav targets on one strip).

6. **`unoptimized` on all `next/image` product renders (`ProductCard.tsx` line 31, `city/page.tsx` line 78).** Every product image opts out of Next's image optimization pipeline. On a real commerce storefront this costs real load-time/LCP, particularly with the large hero-scale image treatments used in `city`/`shrine`/`archive` (some product images render near-viewport-width). Worth confirming this is intentional (e.g. Printful CDN already serving optimized assets) rather than a leftover from local dev.

7. **No loading/skeleton state for BuyButton's async checkout call** — only a text swap (`"Starting…"`). Acceptable for a single button, but there's no protection against double-submit beyond the `disabled` prop being visually silent (see #2) — a fast double-click before the disabled style would register (if it ever did) could double up.

8. **CanceledBanner and error text rely on `text-red` class remapped to `--shop-ink` inside `.shop-design`** (`globals.css` line 277: `.shop-design .checkout-canceled .text-red { color: var(--shop-ink); }`). This flattens error/cancellation state to the same color as all other body copy on the cobalt shop pages, removing the one semantic color cue (red = something didn't complete) that exists elsewhere in the brand palette (`--color-red` is defined and used for `hover:bg-red` on the Tailwind-styled BuyButton in `.agents`-scale pages, but not on the shop-design surface). Minor, but worth a deliberate call rather than a CSS-cascade accident.

## Taste/anti-slop findings (taste-skill)

1. **This is the opposite of AI-template slop — genuinely differentiated composition.** Five hand-tuned layout families (transmission/city, dossier/archive, halo/shrine, wheatpaste/stencil, terminal-grid) each vary grid structure, imagery treatment (grayscale+multiply on archive/shrine, direct color on city), and hero geometry. No centered-hero-over-gradient-blob, no three-equal-feature-cards, no AI-purple. This clears the taste-skill's Section 0/4.3 anti-default bar cleanly.

2. **Real photography used throughout, not fake div-screenshots or stock-purple gradients** (`public/img/shop/graffiti-face.jpg`, `hedge-portrait.jpg`, `skyline-dusk.jpg`, `public/img/products/*`). Matches Section 4.8's real-asset requirement.

3. **Color Consistency Lock is honored per-shop but the chooser page (`app/shop/page.tsx`) mixes registers.** The chooser uses the same cobalt system but numbers each choice with abstract `<i/>` decorative marks (`shop-choice__art`) rather than showing an actual preview thumbnail of each destination page. For a page whose entire job is "help the user pick a direction," showing abstract line/grid/circle glyphs instead of a real screenshot of what `city` vs `archive` vs `shrine` actually look like undercuts the page's function — this reads as an internal design-review artifact (compare five CSS treatments abstractly) rather than a customer-facing decision UI. If this page ships to real users, replace the abstract `<i>` marks with real thumbnail crops of each shop.

4. **Eyebrow discipline: technically over the taste-skill's "1 per 3 sections" cap, but consistent with the mono-label system, not templated.** Every section across `city` (`shop-kicker` appears at hero, catalog header — 2 uses in ~4 sections) and likely each other shop page uses `.shop-kicker` above nearly every heading. Taste-skill's hard rule caps this at ceil(sections/3). This reads less like the generic AI "uppercase-tracking-label-above-everything" tell and more like a deliberate zine/dossier typographic system (mono kicker = a designed content-type marker, reused identically everywhere on purpose, e.g. "Transmission 001", "Approved transmissions / 03"). Still worth a conscious count-and-decide pass rather than assuming it's fine by default — the visual signature depends on this NOT reading as templated, and at high density (5 shop pages × several sections each) it could tip into rhythm-fatigue.

5. **Copy self-audit: mostly clean, a couple of borderline lines.** "We printed the evidence. Three daily objects carrying one unmistakable face." (city hero) and "Transmission ends / goods remain" (city footer) lean toward mock-poetic/forced-metaphor territory the taste-skill flags in Section 4.9 ("reads like an LLM trying to sound thoughtful"). Not broken, but worth a human copy pass — these read as trying hard to sound like copy from a much bigger brand's creative brief.

6. **Shape Consistency Lock: intentionally all-sharp (`--radius: 0px` in `:root` design system, and `.shop-design * { border-radius: 0 !important }`).** This is a documented, enforced rule, not an accident — correctly matches the taste-skill's Section 4.4 requirement that a single corner-radius system be picked and locked. Good discipline.

7. **Bento/grid diversity: the `grid` shop direction (`app/shop/grid/page.tsx`, not fully read but implied by `.grid-catalog`/`.grid-item` CSS) is explicitly the "boring, dense, utilitarian" counterpoint to the other four — the code comment at `globals.css` line 499 calls this out directly, citing supreme.com as reference and noting it's built from familiarity since a live scrape came back empty. That's an honest inline note about sourcing, in line with the taste-skill's honesty rule for borrowed inspiration — good practice, worth keeping.

## Prioritized recommendations

1. **Highest priority — resolve the five-shop chooser before shipping.** Decide which of `city`/`archive`/`shrine`/`stencil`/`grid` is the real storefront, or explicitly gate the chooser behind an internal/review-only route. Shipping `/` → `/shop` (the chooser) as the public entry point turns a design review artifact into the live customer experience.
2. **Fix disabled-state visibility on BuyButton within `.shop-design` pages** — add an explicit `:disabled` rule to the `.shop-design .shop-purchase button` override block in `globals.css` (currently only `:hover` is handled after the `!important` reset wipes Tailwind's `disabled:opacity-60`).
3. **Add a touch-friendly (or at least static, non-broken) fallback for `Mascot3D`** — either a `touchmove` handler or accept it as a static illustration on touch devices; also honor `prefers-reduced-motion` in the JS tilt handler, not just the CSS.
4. **Un-hide real wayfinding copy from screen readers** in `city-hero__signal` / `city-hero__route` (and audit the other four shop pages for the same pattern) — these aren't purely decorative.
5. **Replace abstract glyph previews on the `/shop` chooser page with real thumbnail screenshots** of each destination, so the choice is legible to an actual customer, not just useful for internal design comparison.
6. **Condense the mobile shop-switcher nav** (6 targets in one horizontal-scroll strip) into a clearer pattern — dropdown/hamburger, or a "you are here / switch shop" single control — once the multi-shop question in #1 is resolved (this may become moot if only one shop ships).
7. **Confirm `unoptimized` on product `next/image` usage is intentional**; if not, remove it and let Next's image pipeline handle sizing/format for the storefront's LCP-critical images.
8. **Light copy pass on hero/footer lines** flagged in Taste finding 5 — trim toward plainer, more confident phrasing consistent with the brand's punk/documentary tone rather than reaching for poetic metaphor.
